# Privacy and threat model

## Assets and trust boundaries

Assets are screenshot pixels, diagnostic messages/stacks, page locations, user-written report text, API keys, generated AI text and exported files. The page and all of its scripts are untrusted. The isolated script has a distinct JavaScript environment but shares DOM messages with the page. The background worker and extension UI form the trusted application boundary. Google's API is a separate trust boundary reached only after explicit diagnostic consent. Browser/OS compromise is outside scope.

## Risks and implemented defenses

| Risk | Controls | Residual limitation |
| --- | --- | --- |
| Silent collection or excessive browsing access | Explicit Start, `activeTab`, no website-wide host permissions, no static content scripts, visible status/badge | Collection continues on the originally chosen tab if another tab becomes active; Stop is available in the extension |
| Page error logs contain credentials or personal data | Bounded primitive-only collection; URL query/hash/userinfo removal; known credential/email patterns; worker sanitization; editable review | Arbitrary prose, unknown token formats, URL path segments and truncated values may remain |
| Object serialization reveals state or triggers getters | Omit arbitrary objects; inspect only safe own Error data fields | Primitive strings and Error messages can still disclose private data |
| DOM interaction tracking reveals inputs | Fixed descriptions from a tag allowlist; no text, values, selectors, IDs, classes, or attributes; skip editable targets; opt-in timeline | A sequence of generic actions can still reveal behavior; users may remove it |
| Screenshots reveal credentials, messages, or other personal content | Explicit screenshot, preview, destructive opaque redaction, remove/retake, review gate | Password masking depends on the webpage and browser. Manual review may miss sensitive pixels. |
| A tab switch or navigation substitutes unrelated pixels | Check the active tab, visible top frame, and Chrome document ID before and after capture. Discard the image if activation or navigation occurs during the request. | The browser API captures a window's active tab. These checks depend on Chrome's document identity and event delivery. |
| A page forges diagnostics or floods the bridge | Validate sender extension ID, tab ID, top frame, document ID and session channel. Enforce schema, rate, count, size, and duration bounds. | The page can see the channel, forge plausible diagnostics or suppress events. Reports may omit rate-limited events without an exact count. |
| Page/content script invokes privileged commands | Check the browser-supplied sender ID, top frame and exact packaged editor URL, for both popup and full editor. Validate command schemas. | A compromised extension UI is inside the trust boundary. |
| Content executes in a report preview/export | React escaping, structured text components, plain-text Markdown preview, escaped/fenced exports, fixed ZIP paths and strict JSON import validation | Recipient tools may have their own rendering bugs. Imported screenshots are untrusted binary data with bounded header/dimension checks |
| Stale listeners keep collecting | Explicit cleanup, stop on navigation/tab close, per-session channel, 15-minute page-side deadline | A hostile page can modify its own environment; badge refresh may lag if worker sleeps |
| A failed replacement or edit loses the previous report | Require confirmation tied to the current report ID. Commit a new report only after injection succeeds. Apply edits to worker memory after successful storage writes. Content changes clear review. | Multiple open editors can overwrite each other's stopped draft. Use one editor for report changes. |
| Sensitive data retained unexpectedly | Session storage restricted to trusted contexts, one report, delete-all, no server, no analytics, restrictive CSP | JS memory/storage is not secure erasure; exported files, downloads and OS backups are not deleted by ReproQuill |
| Diagnostic text crosses into a cloud service without informed consent | Optional Google host permission, exact sanitized payload preview and explicit consent tied to the current report evidence. Screenshots and earlier AI output are excluded | Redaction cannot recognize every secret. Google receives the approved text, and its free tier may use inputs/outputs for product improvement. A sent request cannot be recalled |
| API key leaks through a bundle, web page, log or export | User supplies their own key. Session storage by default, optional local retention, trusted-context storage access, key-presence status in settings, authentication header, no raw provider-error display | Browser storage is unencrypted. Local administrators, extension debugging and device compromise can expose a remembered key |
| Prompt injection or fabricated root cause | Versioned instructions treat report text as untrusted evidence. Structured schema, real event-reference membership checks, bounded text rendering and renewed privacy review before export | A model can still give incorrect explanations or unsafe advice. A genuine event reference does not prove causation. Humans verify against source and tests |
| Fabricated analysis metadata or stale results | Provider content excludes provenance. The caller assigns model/prompt/report identity and validates references against exact approved IDs, then rechecks report context at commit | Provider-reported usage is not a billing audit. Legacy strings lack provenance and retain that limitation |
| Repeated requests exhaust quota or add cost | One operation at a time, retries off by default, explicit opt-in attempt budget in consent, backoff/jitter and deadline, no authentication retries or silent model fallback | A billing-enabled key may incur charges. Retries can consume quota. Usage from failed attempts may be unknown |
| Worker restart repeats private transmission | Persist pending metadata and mark unfinished jobs interrupted on recovery without auto-resending | A prior request may already have reached Google even when its response was lost. A user-authorized rerun may repeat the submitted evidence |
| Malformed imported reports or compressed image abuse | Strict versioned JSON and reference validation, review reset, PNG header/metadata dimension equality and a sixteen-million-pixel import bound | Encoded file size is not decoded resource usage. Imported images remain untrusted, and portable JSON cannot restore absent pixels |
| Dependencies or updates add unwanted behavior | Lockfile, small runtime dependency set, licenses, CI, explicit design review of permissions | No independent audit or guarantee against future supply-chain compromise |

## Privacy review checklist for users

Read all text, URLs and stacks; remove or rewrite sensitive details. Inspect the entire screenshot, apply opaque redactions, and save. Review the preview and attachment status. Then explicitly approve the saved report and download it. Share the downloaded file only with intended recipients. Delete all data when finished.

Before running the optional AI diagnostic, inspect the exact text payload and Google's data-use disclosure. Grant permission only if the text is suitable to send to Google. Review the returned suggestions, remove anything inappropriate, and complete export privacy review again. Remove a stored API key when it is no longer needed. Canceling stops local processing where possible, but does not retract text already transmitted.

## Validation

Unit tests exercise credential patterns, object omission, malicious/oversized messages, lifecycle recovery, sender checks, permission failures, deterministic archives, schema/reference validation, retry policy and import limits. Browser tests cover the actual extension UI with synthetic evidence. Normal provider and native-permission boundaries are mocked. The A/B evaluation uses separate human review for subjective quality rather than letting the generator conclusively grade itself. See [verification](VERIFICATION.md) for executed results and [evaluation](EVALUATION.md) for methodology. A test's existence does not establish a passing live-provider result.
